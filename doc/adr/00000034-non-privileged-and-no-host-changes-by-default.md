# 預設不改動主機系統、以非 root 執行；將來的特權擴充必須是可完整移除的 opt-in

> 服務：不變式 4（預設值落向安全）

- **Date:** 2026-11-18
- **Status:** Accepted
- **Relates to:** ADR-00000031（compose 疊加檔與現場部署的預設）、ADR-00000033（新納管預設主機名稱）；#360；與 #361 的區網決定一起檢查（見 Consequences）

## Context

這個專案從規劃起就只依賴 `just`、`docker`、`git`，不要求在主機上安裝額外的 daemon、`sudoers` 規則或特權服務（#360）。現況（main `3a96f98`）：

- 映像以非 root 的服務使用者執行（`Dockerfile` 的 `USER`，uid／gid 由建置參數決定，預設 1000）；compose 檔沒有 `privileged`、`cap_add` 或 `user:` 覆寫。
- 服務只管理掛進容器、而且服務使用者寫得進去的目錄（例如 `/opt/robot/config`）。主機上的目錄由部署者自己建好、設好權限（`doc/DEPLOYMENT.md`）；啟動前檢查在目錄不存在時停下，而不是讓 Docker 用 root 建出來。
- 清單檔的 `requires_privilege` 只在納管時判定並記下「原始 owner／group 不是服務執行身分設得上的」，**沒有任何提權寫出**。

設計文件把「提權寫入」列在不變式 4 那張表：安全的一邊（預設）是「服務不以 root 執行」，opt-in 的一邊是「sudoers 白名單限定特定操作」；附錄 B.3 把它列為未來規劃。將來可能遇到的場景：root Docker（主機上對目標目錄設好權限即可）、rootless Docker（受 user namespace 映射限制，部分擁有者與權限控制做不到——那是 rootless Docker 本身的特性）、要管理 `/etc` 這類由 root 擁有的系統級設定。

## Decision

1. **預設模式不改動主機系統**：啟動、停止、備份、還原與檢查工具都不在主機上安裝軟體、建立服務、寫入 `sudoers`、改防火牆或改系統設定。部署者要做的只有建好目標目錄、設好權限，並把它寫進 `CM_TARGET_ROOT`。
2. **預設以非 root 執行**：服務容器以非 root 的服務使用者執行，不加 `privileged`、不加 capability。目標檔案的擁有者與權限設不上時，照實標記、大聲說明，不為了寫得進去而提權。
3. **將來的特權擴充（例如管理系統級目錄）必須是明確 opt-in 的獨立方案**，並且同時具備：
   - 不打開它時，預設模式的行為與主機狀態完全不變；
   - 完整的安裝與解除（teardown）步驟，移除之後主機上不留殘餘設定（例如 `sudoers` 片段、使用者、群組、服務檔）；
   - 安裝與解除各自可驗證：寫明要怎麼確認裝了什麼、拿掉之後回到原狀。
   設計附錄 B.3 的「提權寫入」若要做，就照這三點設計。
4. **rootless Docker** 不另外提供特殊處理：受 user namespace 限制做不到的擁有者與權限，照第 2 點照實標記；文件寫明這是 rootless Docker 的限制。

## Alternatives

- **服務以 root 執行，換取能寫任何目錄**：一個沒有密碼、身分自我宣告（ADR-00000020）的服務以 root 寫主機檔案，風險落在最不安全的一邊（不變式 4）。
- **預設就裝一條 `sudoers` 白名單**：每台機器都被改動，移除時要有人記得清理；違反「只依賴 `just`、`docker`、`git`」的初衷。
- **為 rootless Docker 自動調整 uid 映射**：要改主機的 subuid／subgid 設定，屬於第 1 點禁止的主機改動。

## Consequences

- 新的部署需求若要改動主機，先照第 3 點寫成獨立的 opt-in 方案（含 teardown 與驗證），不併進預設模式。
- `requires_privilege` 為真的條目，在沒有特權擴充之前就是「寫不出去、照實標記」的那一類。
- **與 #361 的區網決定一致**（維護者 11/14）：區網模式同樣是明確 opt-in 的開關——預設只聽 `127.0.0.1`，打開開關只改服務聽的位址，不改主機系統；若用代理做單一入口，代理也是 compose 裡的獨立容器（#361 留言），不在主機安裝軟體。區網模式不需要提權，與第 2 點不衝突。區網的安全邊界（只限信任的區網、姓名與 email 只用於追溯）由 #361 的 ADR 記錄，不在這裡。
